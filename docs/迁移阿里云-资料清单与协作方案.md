## 0. 一句话结论

现在这套东西跑在一台腾讯云 Windows 服务器上，靠 nssm 当服务托管，三个平台挤在一个 Python 环境里。
迁移到阿里云 Linux + Docker，本质是**把"Windows 服务 + 裸 Python"换成"容器 + 镜像"**。
好消息：仓库里**已经有现成的 `Dockerfile` 和 `docker-compose.yml`**，路径是通的；
真正要你配合的只有三件事：**阿里云账号与一台 ECS、DB 内容确认、旧服务器续费状态**。其余我来做。

## 2. 目标架构（阿里云 ECS Linux + Docker）

### 2.1 为什么选这个（回答你"哪种适合后续迭代"）

- 仓库**已有 Dockerfile + docker-compose**，Linux 容器是现成路径，改造成本最低。
- 迭代时一条 `docker compose up -d --build` 搞定，告别 Windows 上 robocopy + nssm restart + GBK 乱码那套。
- 2C2G 跑 Linux 容器比 Windows Server 省一大截内存，同规格更稳。
- 环境固化在镜像里，**不会出现"本地 pandas 3、服务器 pandas 2"这类漂移**。
- 唯一代价：要学几条 Docker 命令——我可以把更新封装成一条脚本，你只需执行它。

### 2.2 目标布局（建议）

```
阿里云 ECS（Ubuntu 22.04，2C2G）
├─ Docker + docker compose
├─ /opt/litagent/                ← 仓库 clone（应用名硫芯LitAgent）
│   ├─ Dockerfile / docker-compose.yml
│   └─ lis_battery_platform/
├─ /opt/litagent/data/platform.db ← 挂载进容器，持久化
├─ 容器 litagent，restart: unless-stopped，映射 8501:8501
└─ 安全组放行 TCP 8501
```

### 2.3 ⚠️ 关键决策：数据库从哪来

`只迁数据库`——但**旧服务器那台 `platform.db` 内容未知**（可能是旧结构、也可能数据不全，
且我们刚写的 `seed_db.py` 灌库脚本还没在服务器上跑过）。直接搬旧库有风险。

我的方案（推荐）：**用本地 `seed_db.py` 可复现地重建一份干净完整的库**，随代码一起带过去。

- 已验证：从原始 CSV 重建 → 1254 条、schema v3、一致性自检 7/7 全过。
- 好处：干净、可复现、来源清晰（legacy + 文献样本都带 `source_tag`）。
- 代价：旧库里如果有你手工录入且 CSV 中没有的数据，会丢。**这点要你确认。**

备选：如果你确认旧库有独有数据，我给你一条命令从旧服务器导出 `platform.db`，再合并。
