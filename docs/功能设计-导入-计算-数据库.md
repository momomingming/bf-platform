## 1. 文件导入功能

### 1.1 实现思路

单条流水线，五个阶段，每阶段向上汇报进度：

```
读取 → 列映射 → 逐行校验 → 去重 → 事务落库
 20%     30%       75%       85%      100%
```

1. **读取**：按扩展名分流。文本类依次尝试 `utf-8-sig / utf-8 / gb18030 / gbk / big5 / latin1` 解码，分隔符投票选择 `, / \t / ; / |`；Excel 走 `openpyxl`（xlsx/xlsm）与 `xlrd`（xls）。表头自动在文件前 5 行中挑"可识别字段最多"的一行，兼容带说明行的导出文件。
2. **列映射**：表头先做 NFKC 全角转半角 → 去空白 → 剥离 `(m²/g)` 之类单位括号 → 小写，再查别名表。`比表面积 / BET / SSA / surface area` 全部映射到 `specific_surface_area_m2_g`。
3. **校验**：三级——**类型/必填/量纲范围**（ERROR，拒收该行）、**枚举白名单**（WARN，入库但记录）、**跨字段物理一致性**（WARN，如面容量 > 20 mAh/cm²、面比电阻 < 0.05 Ω·cm² 提示复核）。
4. **去重**：`content_hash` = 材料+结构+工况+性能全字段归一化后的 SHA-256（文本去空白转小写，数值按字段精度四舍五入，消除 `1.20000001` 这类浮点尾差）。先批内查重，再与库内 `UNIQUE` 约束比对。
5. **落库**：批次头、样品行、错误明细在同一事务提交。

### 1.2 核心接口

```python
from importer import ImportConfig, import_file, parse_records, build_template, template_to_excel

cfg = ImportConfig(
    battery_type="auto",   # auto | liquid | solid
    dedupe="skip",         # skip=跳过重复 | update=以新数据覆盖
    sheet_name=None,       # Excel 工作表名，None=第一个
    header_row=None,       # None=自动探测
    encoding=None,         # None=自动探测
    delimiter=None,
    strict_mode=False,     # True：存在任一错误行则整批不入库
    source_tag="",
)

def progress(stage: str, pct: float, msg: str) -> None: ...   # 进度回调

report = import_file(file_bytes_or_path, "data.csv", cfg, progress=progress)
report.total_rows / valid_rows / invalid_rows / duplicate_rows
report.inserted_rows / updated_rows / status / errors / warnings
report.missing_columns / unmapped_columns / message / elapsed_ms
```

- `parse_records(df, cfg, progress)`：只解析不落库，供预览/试算使用。
- `build_template(battery_type)` / `template_to_excel(battery_type)`：生成含示例行的空模板（页面上可直接下载）。
- `ImportReport.summary_lines()`：面向用户的四行中文汇总。

### 1.3 校验规则（摘录）

| 字段 | 类型 | 范围 / 枚举 | 违规级别 |
|---|---|---|---|
| 填料类型 | 文本 | 必填 | ERROR |
| 填料负载量(液态) | 数值 | 0 ~ 50 mg/cm² | ERROR |
| 填料含量(固态) | 数值 | 0 ~ 100 wt% | ERROR |
| 比表面积 | 数值 | 0 ~ 5000 m²/g | ERROR |
| 粒径 | 数值 | 0.1 ~ 200000 nm | ERROR |
| 膜/隔膜厚度 | 数值 | 1 ~ 3000 μm | ERROR |
| 孔隙率 | 数值 | 0 ~ 1 | ERROR |
| 温度 | 数值 | −60 ~ 200 °C | ERROR |
| 压力 | 数值 | 0 ~ 1000 MPa | ERROR |
| 倍率 | 数值 | 0.01 ~ 20 C | ERROR |
| 循环次数 | 整数 | 0 ~ 200000 | ERROR |
| 离子电导率 | 数值 | 1e-6 ~ 1000 mS/cm | ERROR |
| 初始比容量 | 数值 | 0 ~ 2500 mAh/g | ERROR |
| 容量保持率 / 库伦效率 | 数值 | 0 ~ 100 % | ERROR |
| 穿梭因子 | 数值 | 0 ~ 1 | ERROR |
| 电化学窗口 | 数值 | 0 ~ 8 V | ERROR |
| 填料类别 | 文本 | 13 类白名单（金属氧化物/氧化物/碳基/硫化物/金属硫化物/卤化物/磷酸盐/硼氢化物/聚合物/MOF-COF/氮化物/复合/其他） | **WARN** |
| 跨字段：面容量 > 20 mAh/cm² | — | — | WARN |
| 跨字段：面比电阻 < 0.05 Ω·cm² | — | — | WARN |

### 1.4 约束条件

- **支持格式**：`.csv / .tsv / .txt / .xlsx / .xlsm / .xls`，单次可多文件；单文件建议 ≤ 20 万行（SQLite 单批事务，超大文件建议拆分）。
- **行级失败不拖垮批次**：错误行只丢弃自己，明细入库可回溯；只有开启 `strict_mode` 才整批回滚。
- **必填列缺失直接终止**：`missing_columns` 非空时不建批次，避免产生脏批次记录。
- **去重键是内容而非主键**：同一条数据换个文件、换个行号照样被识别为重复。
- **覆盖更新不改归属**：`dedupe="update"` 时只更新字段与 `updated_at`，不动 `batch_id`——样品永远归属首次导入批次，批次计数才对得上。
- 单批次最多入库 2000 条错误明细（`MAX_ERROR_ROWS_STORED`），防止一个全错文件撑爆库。

## 2. 精细化计算功能

### 2.1 计算口径（v1.0）

| 指标 | 单位 | 精度 | 计算口径 | 适用 |
|---|---|---|---|---|
| 循环后比容量 `retained_capacity` | mAh/g | 2 | 初始比容量 × 容量保持率 / 100 | 通用 |
| 容量衰减率 `capacity_fade_rate` | %/cycle | 4 | (100 − 容量保持率) / 循环次数 | 通用 |
| 寿命外推 `cycle_life_est` | cycles | 0 | 循环次数 × (100 − EOL) / (100 − 保持率)，线性外推，上限 `max_est_cycles` | 通用 |
| 硫利用率 `capacity_utilization` | % | 2 | 初始比容量 / 理论比容量(1675) × 100 | 通用 |
| 质量能量密度 `energy_density` | Wh/kg | 2 | 循环后比容量 × 标称电压 / 1000 | 通用 |
| 面容量 `areal_capacity` | mAh/cm² | 4 | 负载量(mg/cm²) × 初始比容量 / 1000 | 液态 |
| 面比电阻 `asr` | Ω·cm² | 3 | 膜厚度(μm) × 0.1 / 电导率(mS/cm) | 通用 |
| 参考温度电导率 `conductivity_at_ref` | mS/cm | 5 | σ × exp(−Ea/k_B × (1/T_ref − 1/T))，Arrhenius 外推 | 通用 |
| 穿梭抑制指数 `shuttle_index` | — | 2 | 100 × (1 − min(穿梭因子 / 参考值, 1))，越大越好 | 液态 |
| 综合评分 `composite_score` | — | 2 | 加权求和：容量 / 保持率 / 库伦效率 / 电导率 / 体系附加项（液态=穿梭抑制指数，固态=面比电阻得分），权重自动归一化 | 通用 |
| 表观活化能 `Ea` | eV | 4（批次级） | 按材料分组 ln σ ~ 1/T 线性拟合，**温度点 < 3 不输出结果** | 通用 |

口径说明：
- 能量密度按**循环后**容量计算（工程可用值），不是初始容量——口径在 `METRIC_SPECS.formula` 中显式写明，UI 口径表直接读同一份定义。
- 电导率归一化默认 `Ea = 0.25 eV` 为单点外推的兜底假设；若同一材料有 ≥3 个温度点，用批次级拟合值替代（UI 中可查看）。
- 综合评分各分项先归一化到 0–100 再加权；库伦效率以 90% 为 0 分起点，电导率取 log10 归一化。

### 2.2 参数可配置（`CalcConfig`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `nominal_voltage_v` | 2.1 | 锂硫放电平台标称电压 |
| `theoretical_capacity_mah_g` | 1675 | 硫理论比容量 |
| `ref_temperature_c` | 25 | 电导率归一化参考温度 |
| `activation_energy_ev` | 0.25 | 单点外推表观活化能 |
| `eol_retention_pct` | 80 | 寿命终止判据 |
| `max_est_cycles` | 20000 | 寿命外推上限（防除零/无穷） |
| `shuttle_ref` | 0.15 | 穿梭因子参考值（对应 0 分） |
| `ce_floor_pct` | 90 | 库伦效率评分下限 |
| `conductivity_floor/ceiling_ms_cm` | 0.01 / 10 | 电导率 log 归一化区间 |
| `asr_floor/ceiling_ohm_cm2` | 1 / 200 | 面比电阻评分区间 |
| `weights` | 0.30/0.25/0.20/0.15/0.10 | 综合评分权重，自动归一化 |
| `retention_grades` | A≥90, B≥80, C≥70, D≥60 | 保持率分档 |

### 2.3 关键接口

```python
from metrics import CalcConfig, run_metrics, compute_frame, fit_activation_energy, specs_frame

cfg = CalcConfig(config_name="高电压口径", nominal_voltage_v=2.4, weights={...})
res = run_metrics(samples_df, "liquid", cfg, note="UI计算",
                  source_batch_ids=["B2026..."], progress=cb)
res["run_id"] / ["wide"] / ["params_hash"] / ["result_count"] / ["sample_count"]
```

- `compute_frame(df, bt, cfg)`：只算不落库，用于试算和对比。
- `specs_frame()`：把口径定义导出为表格，UI 与文档共用，保证"说法只有一处"。
- `fit_activation_energy(df)`：批次级 Arrhenius 拟合。

### 2.4 精度与可追溯

- **精度**：统一 `Decimal.ROUND_HALF_UP`（不用 Python 默认的银行家舍入），位数由 `MetricSpec.precision` 决定，**舍入后的值才落库**——界面看到的数与库里的数完全相等，不会"看 2.35 存 2.3499999"。
- **追溯链路**：`metric_runs` 存参数 JSON 快照 + `params_hash` + `formula_version` + 来源批次；`metric_results` 每行带 `inputs_json`（参与本次计算的原始字段值）+ `params_hash` + `formula_version`。
- **改参数不覆盖历史**：参数一变，`params_hash` 变，生成新的 `run_id`，旧 run 完整保留，可随时切换查看/导出/删除。
- **复核示例**：想查某条综合评分为什么是 71.36，展开"单条结果的输入快照"即可看到当次用的初始容量、保持率、库伦效率、电导率。

### 2.5 约束条件

- 输入必须是**已入库**的样品（`metric_results.sample_id` 外键指向 `samples`），不允许"算完不留痕"。
- 缺输入字段的指标**输出空值而非 0**——例如固态体系没有负载量，`areal_capacity` 直接不产出，不用 0 冒充。
- 综合评分缺分项时按**剩余权重归一化**（不会因为少一项就整体偏低）。
- 活化能拟合强制 ≥3 个温度点，避免两点拟合给出假精度。
- `MAX` 类上限（寿命外推 20000 圈）用于拦截数学上的奇异值，不代表物理预测能力。

## 3. 数据库扩充

### 3.1 表结构

存储选型：**SQLite**（stdlib，零依赖，云主机与 Docker 都可直接跑）。路径优先级：环境变量 `BF_DB_PATH` > `lis_battery_platform/data/platform.db`。

| 表 | 作用 | 关键字段 / 约束 |
|---|---|---|
| `samples` | 样品主表 | `id` PK，`content_hash` **UNIQUE**，`batch_id` FK→batches(级联删)，`battery_type` CHECK(liquid/solid)，21 个业务字段 |
| `import_batches` | 导入批次审计 | `batch_id` PK，`file_md5`，行数统计六列，`status`，`params_json`（当时用的导入配置） |
| `import_errors` | 错误/警告明细 | `batch_id` FK(级联)，`row_no`（文件绝对行号）、`code`、`message`、`value`、`severity` |
| `metric_runs` | 计算批次 | `run_id` PK，`params_json` + `params_hash`，`formula_version`，`sample_count`，`result_count`，`source_batch_ids` |
| `metric_results` | 指标结果（长表） | `run_id` FK(级联)，`sample_id` FK(级联)，`metric_code`，`value`，`unit`，`precision`，`inputs_json`，**UNIQUE(run_id, sample_id, metric_code)** |
| `schema_migrations` | 迁移版本记录 | `version` PK，`name`，`applied_at` |

### 3.2 索引

```sql
idx_samples_battery            (battery_type)
idx_samples_batch              (batch_id)
idx_samples_filler             (filler_type)
idx_samples_created            (created_at)
idx_samples_bat_filler_cond    (battery_type, filler_type, temperature_c, c_rate)  -- 体系+材料+工况检索
idx_samples_capacity           (battery_type, initial_capacity_mah_g)              -- 性能排序
idx_batch_file_md5             (file_md5, battery_type)          -- 该文件导入过几次
idx_import_errors_batch / _code
idx_metric_runs_battery / _time
idx_metric_results_run         (run_id, metric_code)             -- 按批次+指标取数
idx_metric_results_sample      (sample_id)
idx_metric_results_value       (metric_code, value)              -- 跨批次指标检索
uq_metric_result               UNIQUE(run_id, sample_id, metric_code)
```

### 3.3 迁移机制

- `MIGRATIONS = [(version, name, [sql...]), ...]`，`init_db()` 按版本号顺序执行未应用的迁移，幂等，可在旧库上原地升级。
- 当前版本 `v2`：`v1` 建全部核心表与索引；`v2` 为批次文件索引（刻意用普通索引而非唯一索引——同一文件允许按不同去重策略重复导入，重复拦截交给行级 `content_hash`）。
- 加字段的正确姿势：**新增一条迁移**，不要把 `v1` 改掉（已部署的库不会再执行旧迁移）。

### 3.4 关键接口

```python
import db
db.init_db()                                   # 迁移到最新，返回本次应用的版本号
db.db_version() / db.db_summary()              # 版本 / 库统计
db.fetch_samples(battery_type, batch_id, limit) -> DataFrame
db.list_batches() / db.fetch_errors(batch_id, severity) / db.delete_batch(batch_id)
db.create_metric_run(meta) / db.save_metric_results(rows)
db.fetch_metric_results(run_id)                # 长表
db.fetch_metric_pivot(run_id)                  # 宽表（一行一样品，一列一指标）
db.list_metric_runs() / db.delete_metric_run(run_id)
db.verify_consistency() -> [{'check','status','detail','count'}]   # 7 项自检
db.compute_content_hash(record, battery_type) / db.compute_params_hash(params)
```

### 3.5 一致性保证

| 机制 | 说明 |
|---|---|
| 事务 | 导入写批次头+样品+错误在同一事务；计算写 run+results 在同一事务 |
| 外键 | `PRAGMA foreign_keys=ON`，删批次级联删样品与其计算结果 |
| 唯一键 | `content_hash` UNIQUE 兜底，即使应用逻辑漏判也进不去重复数据 |
| 计数同步 | 删批次后自动重算受影响 `metric_runs.result_count`（`sync_run_counts()`） |
| WAL | `journal_mode=WAL`，并发读写不互相阻塞 |
| 线程安全 | 连接按 thread-local 复用（Streamlit 多线程场景必需） |

**七项自检**（UI 上一键运行）：

1. 样品内容哈希唯一
2. 批次 `inserted_rows` = 该批次实际样品行数
3. 计算结果无孤儿（`sample_id` 必须存在）
4. `metric_runs.result_count` = 实际结果条数
5. 同一 run 内 `params_hash` 一致（防部分写入时参数被改）
6. 必填字段非空
7. `PRAGMA foreign_key_check` 外键完整性

## 6. 已知限制与后续

1. **Excel 大文件**：`pandas + openpyxl` 全量读内存，超 20 万行建议先拆文件或改流式读取。
2. **并发写入**：SQLite 单写者模型，多人同时导入会在写事务上排队（WAL 已缓解读阻塞）；若未来多人协作，迁 PostgreSQL 只需替换 `db.py` 的连接与 SQL 方言，其余模块不动。
3. **Arrhenius 单点外推**依赖 `Ea=0.25 eV` 假设，材料体系差异大时应以实测多温度数据替换。
4. **指标版本升级**：变更公式时同步提升 `METRIC_VERSION`，旧 run 的 `formula_version` 保留，可做跨版本对比。
5. **备份**：数据库是单文件，直接复制 `data/platform.db`（建议连同 `-wal`/`-shm` 或先 `VACUUM`）。
